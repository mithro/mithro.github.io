# mith.ro

Source for [mith.ro](https://mith.ro) — Tim "mithro" Ansell's personal
site. A static [Jekyll](https://jekyllrb.com/) site built with the
`github-pages` gem and served by GitHub Pages, with a `mith.ro` custom
domain layered on top via CNAME + DNS (see "Deploy & DNS" below).

Pages: home (`/`), talks archive (`/talks/`), papers (`/papers/`),
résumé (`/resume/`), and a 404. Short link redirects live under
`redirects/` (see "Short-link redirects" below) — pending review as of
this writing, so that directory may not exist yet in a fresh checkout.

## Building locally

`vendor/`, `.bundle/`, and `Gemfile.lock` are gitignored, so a fresh
checkout has none of them — gems install locally under `vendor/bundle`
instead of system-wide, and the bundler binary goes to the Ruby user
gem dir, which isn't on `PATH` by default:

```bash
export PATH="$(ruby -e 'print Gem.user_dir')/bin:$PATH"
bundle config set --local path vendor/bundle   # first time only
bundle install                                 # first time only
bundle exec jekyll serve   # http://localhost:4000
```

For a one-off build (e.g. before committing):

```bash
export PATH="$(ruby -e 'print Gem.user_dir')/bin:$PATH"
bundle exec jekyll build   # writes _site/
```

Python helper scripts are run with [uv](https://docs.astral.sh/uv/)
(`uv run scripts/<name>.py`); each script declares its own PEP 723
inline dependencies, so no separate `pip install` step is needed.

## Data files & refresh scripts

Content lives in `_data/*.yaml` and `assets/photos/`. Some are
hand-edited, some are refreshed from external sources with a script:

- **`_data/talks.yaml`** — hand-edited. Originally a snapshot of the
  "Tim 'mithro' Ansell - Talks & Presentations" Google Sheet, plus
  2023-2026 entries compiled from public sources (marked
  `source: compiled` / shown with a ✱ on the site). There is no
  automated fetch script for this sheet — re-snapshot by hand when the
  sheet changes, or paste in new rows as CSV. Per-talk `slug`,
  `talk_title`, `categories`, `series`, `venue`, `strips`, `highlight`
  and `blurb` fields drive the talks section (see "Talks section
  tooling" below); `_data/talk_categories.yaml` is the topic taxonomy.
- **`_data/strips.yaml`** + **`assets/strips/`** — machine-generated
  film-strip thumbnails (one WebP per slide) by
  `scripts/fetch_slide_strips.py` for every talk with `strips: true`.
- **`_talks/`** — machine-generated detail-page stubs, one per talk, by
  `scripts/gen_talk_pages.py`. Re-run after editing `_data/talks.yaml`.
- **`_data/papers.yaml`** — hand-edited snapshot of the Google Scholar
  profile metrics + paper list. Re-snapshot by hand periodically.
- **`_data/resume.yaml`** — hand-edited, structured from the resume
  Google Doc. Re-snapshot by hand when the doc changes.
- **`_data/contact.yaml`** — hand-edited contact links, no source doc.
- **`_data/shortlinks.yaml`** — machine-generated by
  `scripts/fetch_bitly.py`, then hand-reviewed (see "Short-link
  redirects" below). **Local-only and gitignored**: it contains the
  full target URLs and titles of *private* short links, which must
  never appear in this public repo. A fresh checkout won't have it —
  regenerate it with `scripts/fetch_bitly.py` before running
  `scripts/gen_redirect_pages.py`.
- **`assets/photos/`** — wafer.space die/wafer photos, fetched by
  `scripts/fetch_photos.py` from Tim's Google Photos shared albums
  (source URLs recorded in `assets/photos/manifest.yaml`).
  `assets/photos/og-image.jpg` is derived from `die-scan.jpg` by
  `scripts/make_og_image.py` (see below) rather than fetched directly.

### `scripts/fetch_photos.py`

```bash
uv run scripts/fetch_photos.py
```

Downloads the four photos in `assets/photos/` at web resolution from
the shared Google Photos albums hardcoded in the script. After running,
view each image and confirm it still matches its filename before
committing — the source album ordering isn't guaranteed stable.

### `scripts/fetch_bitly.py`

```bash
BITLY_TOKEN=<token> uv run scripts/fetch_bitly.py
```

Fetches every bitlink in the mithro bit.ly group and rewrites
`_data/shortlinks.yaml`. Requires a bit.ly API token with access to
that group, passed via the `BITLY_TOKEN` environment variable — never
commit the token or put it directly on a command line that lands in
shell history (e.g. `read -s BITLY_TOKEN && export BITLY_TOKEN`). No
token is stored anywhere in this repo. Rotate the token periodically
and after any token has been pasted into a terminal, ticket, or chat.

Each generated entry defaults `include: false` with a `reason`, pending
review — except keywords already referenced from public sources (the
talks sheet, the resume), which default to `include: true`, *unless*
they collide with a reserved site path (`talks`, `papers`, `resume`,
`about`, `assets`, `docs`, `scripts`, `404`), in which case they are
always excluded regardless of source. See "Short-link redirects" for
what happens next.

### `scripts/make_og_image.py`

```bash
uv run scripts/make_og_image.py
```

Crops/resizes `assets/photos/die-scan.jpg` (1600x2082 portrait) down to
`assets/photos/og-image.jpg`, a 1200x630 landscape JPEG under 300KB,
used as the `og:image` in `_layouts/default.html`. The full portrait
die scan previews poorly on link-unfurl platforms (Slack, Twitter/X,
etc.), which expect a roughly 1.91:1 landscape image. Re-run after
replacing `die-scan.jpg`; the script auto-lowers JPEG quality until the
result is under the size budget.

## Talks spreadsheet paste-back

`docs/talks-2023-2026-additions.csv` holds 2023-2026 talk rows that
were compiled from public sources (conference programs, YouTube, etc.)
and added to `_data/talks.yaml`, but have **not yet** been pasted back
into the source-of-truth "Tim 'mithro' Ansell - Talks & Presentations"
Google Sheet. Until that paste-back happens, the sheet and
`_data/talks.yaml` are out of sync for those rows (the site is ahead).
Paste the CSV rows in, then this file can be deleted.

## Talks section tooling

`/talks/` is a hub (statistics, talks-per-year chart), with
`/talks/timeline/`, `/talks/highlights/`, a table of topics at
`/talks/topics/` linking to one page per topic at
`/talks/topics/<key>/`, and one detail page per talk at
`/talks/<slug>/`. Everything renders from `_data/talks.yaml` and
`_data/talk_categories.yaml`; the scripts keep the generated parts in
step:

| Script | Purpose |
|---|---|
| `scripts/validate_talks.py` | Data invariants (slugs, categories, highlights, strips manifest). Run before committing `_data/` changes. |
| `scripts/gen_talk_pages.py` | Rebuilds `_talks/` (front-matter stubs; content comes from the layout). |
| `scripts/gen_topic_pages.py` | Rebuilds `_topics/` — one stub per `_data/talk_categories.yaml` entry. Jekyll cannot page a data file, so each topic needs a real file. |
| `scripts/fetch_slide_strips.py` | Exports per-slide thumbnails via the Slides API into `assets/strips/<slug>/` + `_data/strips.yaml`. Slow (the API paces renders); `--only <slug>` / `--force` for one deck. |
| `scripts/fetch_talk_thumbs.py` | First-slide and video thumbnails (unchanged); shares `scripts/slides_api.py` with the strip exporter. |
| `scripts/talks_sheet.py` | Sheet ↔ YAML round-trip for the talks sheets: `slugs` and `strips` push proposals (bold red) into the Slug/Strips columns; `import` pulls Tim's edits back (`--accept` turns the cells black once reviewed); `shortlinks` proposes `mith.ro/<slug>` rows in the short-links sheet for talks with no short link. |
| `scripts/talks_yaml.py` | Comment-preserving field editor used by the above. |

After editing talks (or importing from the sheet): `validate_talks.py`
→ `gen_talk_pages.py` → `fetch_talk_thumbs.py` / `fetch_slide_strips.py`
if decks changed → build. After editing
`_data/talk_categories.yaml`: `gen_topic_pages.py` → `validate_talks.py`
(which fails if a category has no page, a page has no category, or a
category has no talks).

Both Slides-API scripts use gcloud user credentials
(`gcloud auth login --enable-gdrive-access`) with the
`mithro-drive-backup` quota project (`GOOGLE_QUOTA_PROJECT` overrides).

## Short-link redirects

The source of truth for which short links are published is the private
"mith.ro short links" Google Sheet
(docs.google.com/spreadsheets/d/1asrDy1-BwPuOSLjAM79Voz48lmDTeRBF3gWuOmRT2a8):
one row per bit.ly link with a `Visibility` column — `public` rows get
a redirect stub on mith.ro (e.g. `mith.ro/tim-silicon-2024/` → the
long URL), `private` rows do not.

Workflow after editing Visibility in the sheet:

1. Ask Claude to sync `_data/shortlinks.yaml` from the sheet (the YAML
   mirrors it; `include: true` == `public`). Target URLs still come
   from the bit.ly API (`scripts/fetch_bitly.py`) — the sheet only
   governs visibility — except for sheet-native `mith.ro/<alias>` rows
   (added by `scripts/talks_sheet.py shortlinks`), whose target is the
   sheet's "Final URL" column; sync imports those as `source: sheet`
   entries and `fetch_bitly.py` preserves them.
2. Run `scripts/gen_redirect_pages.py` to regenerate `redirects/`
   (one page per public entry, rendered by `jekyll-redirect-from`).
3. Rebuild and verify (see "Verification" below), then commit
   `redirects/` and push.

## Verification

Before committing, do a full build and check every internal link
resolves to a file that Jekyll actually built:

```bash
export PATH="$(ruby -e 'print Gem.user_dir')/bin:$PATH"
bundle exec jekyll build
uv run python - <<'EOF'
import pathlib, re
site = pathlib.Path("_site")
missing = []
for html in site.rglob("*.html"):
    for m in re.finditer(r'href="(/[^"]*)"', html.read_text()):
        target = m.group(1).split("#")[0]
        if target.startswith("//"):
            continue
        p = site / target.lstrip("/")
        if not (p.exists() or p.with_suffix(".html").exists() or (p / "index.html").exists()):
            missing.append((str(html), target))
print("MISSING:", missing if missing else "none")
EOF
```

Expect `MISSING: none`.

## Deploy & DNS

Pushing to `master` deploys to `mithro.github.io` immediately via
GitHub Pages. Getting `mith.ro` itself live additionally requires:

1. **GitHub repo → Settings → Pages**: set the custom domain to
   `mith.ro` (this repo's `CNAME` file already contains `mith.ro`, which
   GitHub Pages reads on deploy) and enable "Enforce HTTPS" once the
   certificate has provisioned.
2. **Cloudflare DNS** for `mith.ro`: point the apex record at GitHub
   Pages, either as
   - `A` records at `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153`, plus `AAAA` records at:
     - `2606:50c0:8000::153`
     - `2606:50c0:8001::153`
     - `2606:50c0:8002::153`
     - `2606:50c0:8003::153`
   - or a CNAME-flatten of the apex to `mithro.github.io`.

   Keep the record grey-clouded (DNS only, not proxied) at least until
   GitHub has provisioned the certificate and "Enforce HTTPS" is
   available — GitHub's HTTP-01 challenge cannot complete through
   Cloudflare's proxy. If you later switch it to orange-clouded, set
   Cloudflare's SSL/TLS mode to "Full (strict)"; plain "Full" does not
   validate the origin certificate and can silently downgrade security.

### Post-push checklist

After pushing and once the DNS change has propagated, spot-check that
a sample of short links land on their long URL, e.g.:

```bash
curl -sL -o /dev/null -w "%{url_effective}\n" https://mith.ro/tim-silicon-2024/
```

Also worth remembering at that point: rotate the bit.ly API token if
it was ever pasted anywhere outside a `read -s` prompt, and follow up
on the two pending review items above (talks spreadsheet paste-back,
shortlinks `include` review).
