# Talks section overhaul — design

Date: 2026-09-05. Branch: `talks-overhaul`.

## Goal

Turn the single chronological `/talks/` page into a proper section:
a hub with statistics, a timeline, a by-topic view, a curated
highlights page, a linkable detail page per talk, and a scrollable
"film strip" of slide thumbnails for every talk whose deck Tim has
cleared for it.

## Constraints that shape the design

- The site builds on the **classic GitHub Pages builder** (Jekyll safe
  mode, github-pages gem). No custom plugins or generators: anything
  that needs a page per data record is produced by a script that writes
  files Jekyll then renders — the pattern `scripts/gen_redirect_pages.py`
  already uses.
- Performance budget: all pages currently score 100/100/100/100 on
  mobile Lighthouse. CSS stays inlined from `_includes/main.css`; images
  are self-hosted WebP with correct `width`/`height`; everything below
  the fold is lazy.
- Data flows are Claude-in-the-loop by design: Google Sheets are Tim's
  review surface, YAML under `_data/` is what the site builds from, and
  scripts move data between the two on request (never in CI).
- Privacy: only slide content Tim has explicitly cleared is exported.
  `_data/shortlinks.yaml` remains gitignored.

## Decisions already taken with Tim

| Question | Decision |
|---|---|
| Which decks get film strips | A new **Strips** column in the talks sheet, imported manually into `talks.yaml` |
| Categories | Claude proposes a taxonomy and assigns all talks; Tim reviews |
| Highlighted talks | Claude proposes 8–10 with reasoning; Tim approves (page shows at most 10) |
| URL structure | `/talks/` becomes a **hub**; timeline, topics and highlights get their own URLs |
| Where strips appear | **Everywhere**: timeline, topics, highlights and detail pages |
| New short links | Only for talks with **no** short link at all, pointing at the deck, else the video |
| Slugs | Every talk has a `slug`; proposals sit in red in the sheet, assumed correct until Tim reviews |
| Hub content | "A whole bunch of fun stats" including talks per year |

## Data model

### `_data/talks.yaml` — new per-talk fields

| Field | Type | Source | Meaning |
|---|---|---|---|
| `slug` | string `[a-z0-9]+(-[a-z0-9]+)*` | done (`talks_sheet.py slugs`) | URL id: `/talks/<slug>/`; equals the short-link alias where one exists |
| `talk_title` | string | Claude, reviewed | Clean title without the event prefix/suffix mashups (`"SymbiFlow - Finally the GCC of FPGAs!"`) |
| `categories` | list of category keys | Claude, reviewed | One or more keys from `_data/talk_categories.yaml` |
| `series` | string, optional | Claude, reviewed | Groups repeat performances of the same talk (`too-many-projects`, `tomu`, `symbiflow-gcc`, `open-down-to-transistor`, `missing-pieces`, `pyhardware`, `why-google-open-silicon`) — powers the "most-repeated talk" stat |
| `venue` | string, optional | Claude, reviewed | Recurring venue key (`lca`, `pyconau`, `ccc`, `orconf`, `riscv-summit`, `chips-alliance`, `darpa-eri`, …) — powers the "favourite venues" stat |
| `strips` | bool | imported from the sheet's Strips column | Export and publish this deck's slide strip |
| `highlight` | int 1..10, optional | Claude proposes, Tim approves | Rank on the highlights page; absence = not highlighted |
| `blurb` | string, optional | Claude, reviewed | One sentence "why it matters", shown on highlights and the detail page |

Existing fields (`title`, `event`, `event_url`, `year`, `date`,
`slides`, `slides_edit`, `slides_embed`, `slides_short`, `video`,
`video_title`, `source`, `sort_date`) are unchanged. `title` stays as
the raw sheet title; templates prefer `talk_title` and fall back to
`title`.

### `_data/talk_categories.yaml` — the taxonomy (new)

Ordered list of `{key, name, blurb}`. Initial proposal, to be refined
while assigning:

| key | name |
|---|---|
| `open-silicon` | Open source silicon (SkyWater PDK, shuttles, OpenROAD, Google's programme, wafer.space) |
| `fpga-tools` | Open FPGA toolchains (SymbiFlow/F4PGA, Yosys, VPR, LiteX) |
| `conference-video` | TimVideos, HDMI2USB and conference capture |
| `tiny-boards` | Tomu and Fomu |
| `python` | Python (PyCon talks, FuPy/MicroPython, GStreamer, libraries) |
| `community` | Community, mentoring and "too many projects" |
| `education` | Education and workforce development |
| `games` | Games and the early (2007–09) talks |

A talk may carry several keys; the topics page lists it under each.

### `_data/strips.yaml` — film strip manifest (generated)

```yaml
# Generated by scripts/fetch_slide_strips.py — do not hand-edit.
<slug>:
  deck: <presentation id>
  count: 27
  w: 480          # true pixel width of the -480 rendition
  h: 270
  slides: [g1a2b3, g4c5d6, ...]   # page objectIds, in deck order
```

Images live at `assets/strips/<slug>/<NN>-240.webp` and `-480.webp`
(`NN` = zero-padded 1-based index). Templates only render strips
present in the manifest, so a deck that failed to export degrades to
today's single thumbnail tile.

### `_data/video_stats.yaml` — deferred

A `{<youtube id>: {views, published, fetched}}` snapshot from the
YouTube Data API would give a "total views" stat and a ranking input
for highlights. It is **out of scope for this plan**: `yt-dlp` is
blocked by YouTube's bot check from this network and the Data API needs
a key to be created first. The hub omits the views stat until a
`scripts/fetch_video_stats.py` exists; highlights are ranked without
it.

## Sheet workflow — `scripts/talks_sheet.py`

Matches rows on every tab of the original talks sheet
(`10TQ8mG…`: Slides, YouTube) and the additions sheet (`1oaJnQU…`) to
`talks.yaml` entries using the strongest available identifier: deck id
> YouTube id > short alias > slug > normalised title. Idempotent.

| Subcommand | Direction | What it does |
|---|---|---|
| `dump` | sheet → stdout | JSON of all tabs with row↔talk matches (debugging) |
| `slugs` | YAML → sheet | Writes the Slug column (done). Black = existing alias, bold red = proposal |
| `strips` | YAML → sheet | Adds a **Strips** column next to Slug, pre-filled `yes` (red) for decks that are publicly fetchable today (present in `_data/thumbs.yaml`), blank for restricted decks. Never overwrites a cell Tim has already filled |
| `import` | sheet → YAML | Reads Slug and Strips back: updates `slug:` textually (comments preserved, as `enrich_talk_embeds.py` does); a Strips cell of `yes` (case-insensitive) writes `strips: true`, anything else removes the `strips:` line. Then turns imported Slug/Strips cells black to show they are accepted |
| `shortlinks` | YAML → shortlinks sheet | For each talk with no short link at all, appends a row `mith.ro/<slug>` → deck URL (else video URL), Visibility `private`, Source `talk`, for Tim's review |

`import` (and `validate_slugs`) refuses a slug that collides with
another talk, an existing short link, or one of the reserved names
under `/talks/` — `timeline`, `topics`, `highlights`, `feed` — and
reports what it changed.

`format_sheets.py sync` gains one behaviour: rows in the shortlinks
sheet whose alias is in no YAML entry are appended to
`shortlinks.yaml` as sheet-native entries (`source: sheet`, no
bit.ly), and `fetch_bitly.py` preserves `source: sheet` entries when it
regenerates the file. `gen_redirect_pages.py` needs no change.

## Film strips — `scripts/fetch_slide_strips.py`

- uv/PEP 723 script; auth via `gcloud auth print-access-token`
  (Drive scope covers the Slides API); sends
  `X-Goog-User-Project: mithro-drive-backup` — the same quota project
  and `GOOGLE_QUOTA_PROJECT` override `fetch_talk_thumbs.py` already
  uses for its first-slide `getThumbnail` calls. The Slides-API helper
  (token, headers, backoff, the 1.5 s per-render pacing) is shared with
  that script rather than duplicated.
- For every talk with `strips: true` and a Google Slides deck id
  (from `slides_edit`, else `slides`, else `slides_embed`; `/d/e/`
  published ids are not usable and are reported):
  1. `GET presentations/{id}?fields=slides.objectId,pageSize` — slide
     order and aspect ratio.
  2. For each slide, `GET presentations/{id}/pages/{objectId}/thumbnail?thumbnailProperties.thumbnailSize=MEDIUM`
     (800 px PNG, URL valid 30 min), download, and write `-480.webp`
     and `-240.webp` with Pillow (quality 70, same as
     `fetch_talk_thumbs.py`).
  3. Record the manifest entry.
- Incremental: a slug whose manifest entry matches the deck's current
  slide-id list is skipped; `--force <slug>` re-exports one deck.
  Removing `strips: true` from a talk makes the script delete its
  directory and manifest entry (so the sheet stays the authority).
- Rate limiting: thumbnails are "expensive reads"; the script uses a
  small thread pool with exponential backoff on HTTP 429/5xx and prints
  a per-deck summary. Failures (403 deck gone, deleted deck) are
  reported and leave no partial directory.
- Expected footprint: ~105 decks × ~25 slides × (~6 KB + ~15 KB) ≈
  25–40 MB. Acceptable for GitHub Pages; noted for the repo.

## Pages and URLs

| URL | File | Content |
|---|---|---|
| `/talks/` | `talks/index.html` | Hub: stats band, talks-per-year chart, category breakdown, cards to the three sub-pages, teaser of the top 3 highlights |
| `/talks/timeline/` | `talks/timeline/index.html` | Today's chronological listing, each talk with a strip |
| `/talks/topics/` | `talks/topics/index.html` | Same rows grouped by category, in taxonomy order |
| `/talks/highlights/` | `talks/highlights/index.html` | The curated set in rank order, with blurb, strip and embeds |
| `/talks/<slug>/` | `_talks/<slug>.md` (generated) via `_layouts/talk.html` | Full detail page |
| `/talks/feed.xml` | unchanged path | Items now link to the detail page |

Nav keeps a single "Talks" entry pointing at `/talks/`; the four talks
pages share a small sub-nav (`Hub · Highlights · Timeline · Topics`)
rendered by `_includes/talks_nav.html`.

### Hub statistics (all computed in Liquid at build time)

- Talks given, recordings available, decks with slides, slides
  published across strips (sum of `strips.yaml` counts)
- Years speaking (`first year – latest year`), busiest year
- Talks per year: a CSS bar chart (one `<div>` per year, height as a
  percentage of the busiest year, year labels, counts on hover and in
  a visually-hidden table for screen readers); the undated talk is
  excluded
- Distinct events; favourite venues (top 5 by `venue`)
- Category breakdown (count per category, linking into `/talks/topics/#<key>`)
- Most-repeated talks (top 3 `series` by count, with year span)
- Total YouTube views, if `video_stats.yaml` exists

Counters reuse the existing `dl.spec` styling from the home page.

### Detail page (`_layouts/talk.html`)

Title (`talk_title`), event (linked) and date, category chips linking
to the topics page, the film strip (larger: 200 px tall), the
click-to-load slides and video embeds exactly as on the timeline
today, the talk's short link when it is a public alias, the blurb when
present, and prev/next links in date order. `og:image` becomes the
deck's existing 640 px thumbnail when available, so shared links get a
slide preview.

### Generated collection — `scripts/gen_talk_pages.py`

Writes `_talks/<slug>.md` with front matter `{slug, title, permalink:
/talks/<slug>/}` only; all content comes from `site.data.talks` looked
up by slug in the layout, so regenerating never touches content.
`_config.yml` declares `collections: talks: {output: true, permalink:
/talks/:name/}`. The `_talks/` directory is rebuilt from scratch on
each run (idempotent, like `redirects/`).

## Film strip component — `_includes/strip.html`

```html
<div class="strip" role="group" aria-label="Slides: {{ talk_title }}">
  <a href="{{ deck }}#slide=id.{{ objectId }}" ...>
    <img src="…/01-240.webp" srcset="…/01-240.webp 240w, …/01-480.webp 480w"
         sizes="240px" width="480" height="270" loading="lazy" decoding="async"
         alt="Slide 1 of 27">
  </a> …
</div>
```

- `overflow-x: auto`, `scroll-snap-type: x proximity`, thin custom
  scrollbar, 135 px tall frames (`aspect-ratio` from the manifest),
  gap 0.35 rem; keyboard-reachable (each frame is a link); hover
  raises the frame slightly, disabled under `prefers-reduced-motion`.
- The strip's block wrapper (inside the table cell — `content-visibility`
  does not apply to table rows) gets `content-visibility: auto` with a
  `contain-intrinsic-size` hint so 121 strips cost nothing until they
  scroll near the viewport; images are lazy, so real fetches track
  what the visitor actually looks at.
- On listing pages the strip **replaces** the single slides tile
  (the video tile stays alongside); on the detail page the strip sits
  above the full slides and video embeds.
- **Implementation finding (2026-09-05):** the decks total 8,340 slides
  (average 74, up to 176), not the ~25 per deck assumed above. Detail
  pages show every frame; listing rows show the first 12 (highlights:
  24) followed by a "+N more" frame that links to the detail page, so
  the timeline carries ~1,500 frames rather than ~8,000. The asset
  footprint is ~200 MB rather than 25–40 MB.
- Each frame links to the deck at that slide: the docs.google.com
  `/presentation/d/<id>/edit#slide=id.<objectId>` URL derived from the
  deck id (never a bit.ly link, whose redirect may drop the fragment).
  Decks without a usable id fall back to a non-link frame.
- The click-to-load embed tiles and their swap-in script move from
  `talks/index.html` into `_includes/talk_embeds.html` so the four
  listing pages and the detail layout share one implementation.

## Highlights selection

Candidates are ranked by: recording views (if available), venue
reach (CCC congress/camp, LCA keynote-track, RISC-V Summit, DARPA
ERI), and how often the talk was re-invited (series size). Claude
proposes 8–10 with a one-line justification each in the PR
description; Tim trims/re-orders by editing `highlight:` ranks. The
page shows at most 10.

## Sequencing

sync` extension, the `fetch_bitly.py` preservation rule) touches a
different sheet and the private `shortlinks.yaml`, and nothing on the
site depends on it: it is the last task and independently mergeable.

`ci-previews-linkcheck` (PR #1, unmerged). Verification steps 3–4 below
